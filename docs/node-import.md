SMV-VPN: добавление узлов — ссылки, ключи, QR-коды
Дополнение к брифу. Описывает функциональность импорта/добавления подключений для всех целевых платформ.

1. Способы добавления узла (сводная таблица)
Способ	Windows	Linux	macOS	Android	iOS
Вставка ссылки из буфера обмена	✅	✅	✅	✅	✅
Ручной ввод ссылки в поле	✅	✅	✅	✅	✅
Импорт из файла (JSON/YAML/txt)	✅	✅	✅	✅	✅ (Files)
Сканирование QR-кода камерой	⚠️ опц.	❌	⚠️ опц.	✅	✅
Сканирование QR-кода из изображения/скриншота	✅	✅	✅	✅	✅
Показ собственного QR-кода узла	✅	✅	✅	✅	✅
Множественный импорт (список ссылок)	✅	✅	✅	✅	✅

Обозначения: ✅ обязательно, ⚠️ опционально (зависит от наличия камеры/политики ОС), ❌ не требуется.

Ключевое ограничение: камера есть только на мобильных и (опционально) на ноутбуках. Поэтому обязательный минимум для десктопа — вставка из буфера и сканирование QR из файла изображения (скриншот, фото). Прямое сканирование камерой на десктопе — опция.

2. Поддерживаемые форматы «ключей» и ссылок
Парсер (SMV.LinkParser) должен принимать:

2.1. Прокси-URI

vless://<uuid>@<host>:<port>?<params>#<name> — с поддержкой Reality (security=reality, pbk, sid, fp, sni, flow), транспортов tcp, ws, grpc, httpupgrade, xhttp.

hysteria2://<auth>@<host>:<port>?<params>#<name> — sni, insecure, obfs, obfs-password, up/down.

hy2://... — алиас Hysteria2.

tuic://<uuid>:<password>@<host>:<port>?<params>#<name> — congestion_control, alpn, sni.

trojan://<password>@<host>:<port>?<params>#<name>.

ss://<base64(method:password)>@<host>:<port>#<name> и SIP002-формат.

socks://, http:// — для ручного прокси.

wireguard:// — опционально.

2.2. Составные форматы

Base64-подписка: строка в Base64, внутри — список URI, разделённых переводом строки.

sing-box JSON: массив outbounds — извлекаются узлы, совместимые с поддерживаемыми протоколами.

Clash YAML: секция proxies — конвертация в SMV.ConfigModel.

Xray/V2Ray JSON: секция outbounds — извлечение VLESS/VMess/Trojan/SS.

«Голый» список ссылок: несколько URI через \n, \r\n, пробел или запятую.

2.3. Что считается «ключом» в UI
Пользователь видит единое поле «Вставьте ссылку или ключ». Парсер сам определяет тип по префиксу (vless://, hysteria2://, base64, {/[ для JSON, proxies: для YAML). При неудаче — понятная ошибка с указанием, что не распознано.

3. QR-коды: генерация и сканирование
3.1. Генерация QR (показ узла)

На экране узла — кнопка «Поделиться / QR».

QR кодирует исходную URI-ссылку узла (не JSON) — так его прочитает любой совместимый клиент (v2rayN, Hiddify, Streisand, sing-box-клиенты).

Для подписки — QR кодирует URL подписки.

Экспорт QR как PNG (десктоп) / «Сохранить в Фото» (мобильные) — опционально.

Требование: QR-генератор работает офлайн, без внешних сервисов (приватность).

3.2. Сканирование QR камерой (мобильные)

Android: CameraX + ML Kit Barcode Scanning (или ZXing). Запрос разрешения камеры по требованию. После распознавания — предпросмотр узла и кнопка «Добавить».

iOS: AVCaptureSession + Vision (VNDetectBarcodesRequest) или AVCaptureMetadataOutput. Запрос NSCameraUsageDescription в Info.plist.

Сканирование непрерывное (пользователь наводит камеру, приложение ловит первый валидный URI), с возможностью отмены.

Если QR содержит не URI, а base64/JSON — парсер обрабатывает как обычный импорт.

3.3. Сканирование QR из изображения (все платформы)
Это обязательный способ для десктопа и полезный для мобильных (скриншоты).

Пользователь выбирает файл (PNG/JPG/WebP) или перетаскивает его в окно (drag-and-drop на десктопе).

Декодирование QR из изображения — офлайн, без отправки на сервер.

Библиотеки:

Flutter: mobile_scanner (камера + изображения), qr_code_scanner, zxing2.

Rust/Tauri: rqrr или quircs (чистый Rust, офлайн) для декодирования; qrcode для генерации.

Нативные: Android ML Kit (offline mode), iOS Vision.

Поддержка нескольких QR на одном изображении — опционально (например, скриншот списка узлов).

3.4. Особые случаи

QR с несколькими ссылками (base64-подписка) — импорт всех узлов с предпросмотром списка.

Повреждённый/частичный QR — понятная ошибка «QR не распознан», без падения.

QR, содержащий неподдерживаемый протокол — сообщение «Протокол не поддерживается».

4. UX-поток добавления (единый на всех платформах)
Кнопка «+» на экране Servers.

Меню выбора способа:

Из буфера обмена (если в буфере есть распознаваемая строка — показывается сразу).

Вставить вручную (поле ввода + кнопка «Разобрать»).

Сканировать QR (камера — мобильные; на десктопе скрыто/опционально).

Из изображения (файл/скриншот/drag-and-drop).

Из файла (JSON/YAML/txt).

Добавить подписку (URL + интервал обновления).

Предпросмотр: карточка узла (протокол, адрес, порт, транспорт, имя), кнопка «Добавить» / «Отмена». При множественном импорте — список с чекбоксами.

Валидация: проверка обязательных полей, предупреждения (например, insecure=true, отсутствие sni для Reality).

Узел появляется в списке, готов к выбору.

5. Модель данных: расширение SMV.ConfigModel
Минимальные поля узла (v0.1):

json
{
  "id": "uuid-v4",
  "name": "My VLESS Reality",
  "protocol": "vless",
  "server": "example.com",
  "port": 443,
  "uuid": "...",
  "flow": "xtls-rprx-vision",
  "transport": { "type": "tcp" },
  "security": {
    "type": "reality",
    "sni": "example.com",
    "fingerprint": "chrome",
    "public_key": "...",
    "short_id": "..."
  },
  "tags": ["work"],
  "source": {
    "type": "uri | qr | file | subscription",
    "raw": "vless://...",
    "imported_at": "2026-11-16T00:00:00Z"
  }
}
Поле source хранит исходную ссылку — это нужно для генерации QR при «поделиться» и для переэкспорта.

6. Требования по безопасности и приватности
QR-декодирование и парсинг — только локально, без сетевых запросов.

Разрешения камеры запрашиваются по требованию и только при открытии сканера.

Буфер обмена: при вставке не логируется содержимое; в логах — только тип распознанного формата.

Секреты (UUID, пароли, private key) не отображаются в списке узлов; доступны только в редакторе с маскировкой.

Экспорт QR с секретами — с предупреждением «QR содержит ключи доступа».

8. Критерии готовности функции (Definition of Done)
□ Вставка vless:// (Reality) и hysteria2:// из буфера → предпросмотр → добавление.
□ Импорт base64-подписки с несколькими URI → предпросмотр списка → массовое добавление.
□ Импорт sing-box JSON и Clash YAML (извлечение узлов).
□ Генерация QR из узла → сканирование этого QR другим устройством → успешный импорт (round-trip тест).
□ Декодирование QR из PNG/JPG на десктопе.
□ Сканирование камерой на Android и iOS с запросом разрешения.
□ Понятные ошибки для неподдерживаемых/битых ссылок и QR.
□ Никаких сетевых запросов при парсинге и декодировании.
□ source.raw сохраняется и используется для экспорта QR.

## 9. Уточнения при реализации (v0.1, пакет `packages/smv_link_parser`)

- **VMess** поддерживается в обоих видах: `vmess://BASE64(JSON)` (v2rayN) и `vmess://uuid@host:port?…`.
- **Port hopping Hysteria2**: в модели добавлено поле `port_range` (`443,20000-30000`); `port` — первый порт диапазона.
- **URL подписки**: парсер не ходит в сеть. `https://…` (и `http://…` с путём, без логина) возвращаются в `subscriptionUrls`; загрузка — отдельное явное действие пользователя.
- **Экспорт QR**: `shareUri()` отдаёт `source.raw`, если узел пришёл одной ссылкой; иначе (JSON/YAML или узел изменён в редакторе) — `nodeToUri()` собирает ссылку из модели. После правки узла `source.raw` нужно обновлять.
- **Reality**: отсутствие `sni` или `pbk` — ошибка (узел не добавляется), отсутствие `fp` — предупреждение.
- **flow** допустим только с `tcp` + TLS/Reality.
- **Дубликаты**: внутри одного импорта схлопываются по (протокол, адрес, порт, учётные данные); `LinkParser.duplicateIds()` — для пометки «уже добавлен» и обновления подписок.
- **Секреты**: ошибки разбора не содержат исходной строки; для логов — `ProxyNode.toRedactedJson()`. `source.raw` содержит ключи и должен храниться в защищённом хранилище (Keychain / Keystore).
- **xhttp** разбирается, но работает только с ядром Xray — учесть при выборе ядра в `docs/decision-stack.md`.
- **Clash `network: http`** — это HTTP-заголовок поверх TCP, а не h2.
